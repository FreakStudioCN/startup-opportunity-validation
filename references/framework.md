# Unified opportunity-validation framework

The workflow is:

`public evidence → demand-behavior signal → problem cluster → opportunity structure → lifecycle calibration → 3–7 day experiment → Kill / Modify / Escalate / Deliver`

## Layers

| Layer | Question | Primary material |
| --- | --- | --- |
| Discovery | Where is a user already behaving as if a problem exists? | Cross-14-signal funnel |
| Structure | Does this resemble a viable, testable business? | Opportunity-structure research |
| Calibration | Is the signal attention or re-selection/money/use? | Lifecycle research |
| Experiment | What cheapest action can falsify the main unknown? | Multi-direction validation analysis |

## Evidence hierarchy

0: team belief; 1: online discussion; 2: user-initiated request/search; 3: response to outreach; 4: meeting, data, or introduction; 5: price/solution request; 6: accepted quote, LOI, procurement; 7: deposit, preorder, paid pilot, or payment; 8: repeat use, retention, renewal, or expansion.

Evidence levels 0–2 create a lead. A formal experiment should be designed to reach levels 4–7; levels 7–8 are the strongest commercial evidence.

## Decision logic

- **Kill:** the core proposition fails its predeclared threshold or decisive contrary evidence appears.
- **Modify:** evidence exists but buyer, problem, offer, price, or channel is wrong.
- **Escalate:** users request a quote, provide data, accept a pilot, or enter a purchasing path.
- **Deliver:** a customer commitment justifies a manual or semi-automated delivery.

Never hide an untested premise behind an aggregate score. State the evidence gap and select the experiment that reduces it most.
