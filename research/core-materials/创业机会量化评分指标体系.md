# 创业机会量化评分指标体系

## 0. 这份文档解决什么问题

这份文档把当前四份核心材料里的判断标准，整理成一套可以打分、排序、复盘的指标体系。

四份核心材料是：

| 文档 | 作用 |
| -- | -- |
| `初创多方向假设验证综合分析.md` | 告诉我们怎么做 3-7 天低成本商业实验 |
| `机会结构特征综合研究报告.md` | 告诉我们什么样的机会结构更值得验证 |
| `跨14类Signal机会漏斗综合报告.md` | 告诉我们怎么从海量讨论里发现机会 |
| `产品生命周期行为信号跨品类有效性研究报告.md` | 告诉我们哪些公开行为信号更硬，哪些只是热度 |

本指标体系的目标不是预测创业一定成功，而是回答：

> 如果明天拿到 100 个陌生创业机会，在没有开发产品的情况下，哪些机会应该优先进入 3-7 天商业实验？

所以这套分数应该叫：

> **Opportunity Pre-Screen Score，机会实验前筛选分**

它不是：

- 成功率预测；
- ARR 预测；
- 融资概率预测；
- 投资决策模型；
- 严格因果模型。

它是：

- 机会排序工具；
- 实验优先级工具；
- 证据缺口识别工具；
- Kill / Modify / Escalate 的辅助工具。

## 1. 当前数据够不够

结论：

> 当前数据够做 v1 评分体系，不够做严格成功预测模型。

### 1.1 当前已有数据

| 数据来源 | 当前规模 | 主要用途 |
| -- | --: | -- |
| 14 类 Demand Behavior Signal | 140000 条 | 判断问题是否有真实行为痕迹 |
| 去重独立证据 | 125411 条 | 判断证据是否来自多个独立来源 |
| 跨 Signal 机会评分 | 30 个问题簇 | 判断哪些问题簇更值得进入实验 |
| 近两年机会结构案例 | 1000 条 | 判断近两年机会结构共性 |
| 深度成功/失败案例库 | 49 条 | 判断结构变量在成功/失败中的差异 |
| 产品生命周期信号 | 150 个 anchor / 27000 行 | 判断产品行为链强弱 |
| 近两年 1000 项目生命周期信号 | 1000 项目 / 40000 行 | 判断近两年新项目的行为链完整度 |
| 本地原始 JSON | 10 万级 | 追溯原始证据 |

### 1.2 当前够支撑的判断

现有数据足够支撑：

- 有没有公开需求信号；
- 有没有 workaround；
- 有没有重复劳动；
- 有没有自建工具；
- 有没有迁移/替代；
- 有没有现有预算；
- 有没有问价/试用/采购意图；
- 有没有真实使用、支持、抱怨；
- 某个机会是否只是热度；
- 某个机会是否更值得进入 3-7 天实验。

### 1.3 当前不够支撑的判断

现有数据不足以严格支撑：

- 真实付费转化率；
- 真实 CAC；
- 真实 LTV；
- 真实毛利；
- 真实留存；
- 真实复购；
- 真实融资概率；
- 严格成功概率；
- 严格因果关系。

所以这套指标必须明确：

> 它用于决定“先验证谁”，不是决定“谁一定成功”。

## 2. 总分结构

建议总分为 100 分，另设扣分项。

| 模块 | 分数 | 核心问题 |
| -- | --: | -- |
| A. 需求行为信号 | 20 | 用户是否已经表现出真实需求行为 |
| B. 机会结构质量 | 20 | 这个机会本身的骨架是否好 |
| C. 生命周期信号硬度 | 20 | 公开信号处在围观、问价、试用、使用还是复购阶段 |
| D. 实验可执行性 | 20 | 能否在 3-7 天内低成本验证 |
| E. 商业化与扩张潜力 | 20 | 是否可能形成持续收入和扩张 |
| F. 反面信号扣分 | -50 到 0 | 是否存在明显伪机会特征 |

最终分数：

```text
总分 = A + B + C + D + E - 反面信号扣分
```

## 3. A 类指标：需求行为信号，20 分

对应文档：

`跨14类Signal机会漏斗综合报告.md`

这一项看的是：

> 用户有没有已经在做什么，而不只是嘴上说有兴趣。

### 3.1 评分表

| 指标 | 分数 | 怎么判断 |
| -- | --: | -- |
| 已有替代方案 / workaround | 4 | 用户已经用 Excel、脚本、外包、旧软件、内部系统解决 |
| 重复劳动 | 3 | 问题反复发生，不是一次性麻烦 |
| 自建工具 / 自己造轮子 | 3 | 用户愿意花时间写脚本、插件、内部工具 |
| 已经花钱但不满意 | 4 | 用户已经买过软件、服务、人力或外包 |
| 迁移 / 找替代 | 3 | 用户正在比较、替换、迁移 |
| 多来源独立证据 | 3 | 不是单个帖子，而是多个作者、多个来源反复出现 |

### 3.2 大白话解释

如果用户已经在用很笨的方法解决问题，这比“用户说有需求”重要。

如果用户已经花钱但不满意，这比“用户觉得有趣”重要。

如果很多不同用户都在绕路、自建、迁移，这比一条爆款帖子重要。

| -- | -- |

| `demand_behavior_signal_research/metadata/signal_summary.csv` | 14 类 signal 汇总 |
| `demand_behavior_signal_research/opportunity_funnel/metadata/01_deduplicated_evidence.csv` | 去重证据 |
| `demand_behavior_signal_research/opportunity_funnel/metadata/02_cross_signal_opportunity_scores.csv` | 问题簇分数 |

## 4. B 类指标：机会结构质量，20 分

对应文档：

`机会结构特征综合研究报告.md`

这一项看的是：

> 这个机会是不是长得像一个能成立的生意。

### 4.1 评分表

| 指标 | 分数 | 怎么判断 |
| -- | --: | -- |
| 目标用户足够窄 | 3 | 能说清谁最痛，而不是“所有人都需要” |
| 痛点强度高 | 4 | 不解决会损失钱、时间、机会、合规、安全或收入 |
| 单次价值清晰 | 3 | 一次解决能节省/赚到/避免多少损失 |
| 价值发生频率合适 | 3 | 高频、周期性、或低频但高价值 |
| 替代方案明确 | 3 | 知道用户现在怎么解决 |
| 价值表达清楚 | 2 | 5-10 秒能讲明白 |
| 小切口后可扩张 | 2 | 不是只能做一个很小的一次性工具 |

### 4.2 大白话解释

好机会通常不是“没人做过”，而是：

> 已经有人在解决，但解决得很痛苦、很贵、很慢、很不稳定。

没有替代方案不一定不好，但早期验证会更难。因为你不知道用户是不是真的在乎。

## 5. C 类指标：生命周期信号硬度，20 分

对应文档：

`产品生命周期行为信号跨品类有效性研究报告.md`

这一项看的是：

> 公开讨论里的信号，到底只是围观，还是已经接近商业动作。

### 5.1 评分表

| 指标 | 分数 | 怎么判断 |
| -- | --: | -- |
| 有搜索/发现信号 | 2 | Search、Launch、Show HN、Solution Discovery |
| 有求推荐/比较信号 | 3 | Recommendation、Comparison |
| 有找替代/迁移信号 | 4 | Alternative Seeking、Switching |
| 有问价/报价/购买意图 | 4 | Pricing、Quote、Purchase Intent、Vendor Search |
| 有试用/安装/上手 | 3 | Trial、Installation、Onboarding |

```text

```

最重要的判断：

> 只有热度不够，必须看用户是否进入重新选择、问价、试用、使用。

## 6. D 类指标：实验可执行性，20 分

对应文档：

`初创多方向假设验证综合分析.md`

这一项看的是：

> 这个机会能不能在 3-7 天内问市场要到强证据。

### 6.1 评分表

| 指标 | 分数 | 怎么判断 |
| -- | --: | -- |
| 能写成可证伪命题 | 3 | 成功/失败标准清楚 |
| 能写出最小可销售 Offer | 4 | 可以卖一个具体结果，而不是卖愿景 |
| 能找到 30-100 个目标用户 | 4 | 有名单、社区、论坛、GitHub、公司列表、职位关键词 |
| 能低成本触达 | 3 | 冷邮件、私信、社区回复、帖子、转介绍可行 |
| 能人工/半自动交付一次 | 3 | 不需要先做完整产品 |
| 能定义强信号 | 3 | 回复、会议、数据、报价、定金、Paid Pilot、付款 |

### 6.2 大白话解释

一个机会再好，如果你 7 天内找不到人、说不清 Offer、拿不到下一步行为，也不适合当前阶段。

当前阶段要优化的是：

> 每次实验买到多少有效信息。

而不是：

> 页面做得多好、功能做得多完整、想法讲得多漂亮。

## 7. E 类指标：商业化与扩张潜力，20 分

对应文档：

`机会结构特征综合研究报告.md`

这一项看的是：

> 即使有人愿意试，这个机会后面能不能变成持续收入。

### 7.1 评分表

| 指标 | 分数 | 怎么判断 |
| -- | --: | -- |
| 收费方式匹配价值发生方式 | 4 | 高频订阅、低频高价项目费、使用量收费、合同等匹配 |
| 有持续需求 | 4 | 用户一个月后、一年后仍然需要 |
| 有 workflow / data / team 嵌入 | 3 | 使用越久越有价值 |
| 交付成本可下降 | 4 | 人工服务可以逐步自动化，AI 成本可控 |
| 获客机制可重复 | 3 | 不只靠一次性发帖或创始人流量 |
| 有扩张路径 | 2 | 小切口可以扩到更大流程、更多用户或更高客单 |

### 7.2 大白话解释

早期能赚第一笔钱很好，但还要问：

- 是不是每个客户都要大量人工定制？
- 是否越卖越累？
- 毛利是否会被 AI 推理、售后、集成、供应链吃掉？
- 用户是不是只用一次？
- 下一个客户是不是还要从零开始解释？

如果答案都不好，这可能是服务项目，不一定是可规模化产品。

## 9. 总分分层

| 总分 | 决策 | 应该怎么做 |
| --: | -- | -- |
| 80+ | 立即进入 3-7 天实验 | 直接写 Offer、找名单、冷邮件/私信/报价 |
| 65-79 | 值得客户发现或报价测试 | 先补关键证据，尽快撞 Money / Activation |
| 50-64 | 暂不做产品，先补桌面研究 | 补替代方案、买家、预算、触达路径 |
| 35-49 | 低优先级观察 | 放入 watchlist，不占用实验资源 |
| <35 | 暂时杀掉 | 除非出现新证据，否则不进入实验池 |

## 10. 证据等级和分数关系

来自 `初创多方向假设验证综合分析.md` 的证据等级，可以映射到分数权重。

| 证据等级 | 行为 | 对评分的意义 |
| --: | -- | -- |
| 0 | 我们觉得 | 不加分 |
| 1 | 网上有人讨论 | 只给线索分 |
| 2 | 用户主动发帖/搜索/求助 | 可加需求行为分 |
| 3 | 用户回复冷邮件/私信 | 可加实验可执行性分 |
| 4 | 用户愿意开会/给数据/介绍同事 | 强化痛点和可触达性 |
| 5 | 用户主动问价格/要方案 | 强商业意图 |
| 6 | 用户接受报价/LOI/采购流程 | 可进入升级实验 |
| 7 | 定金/预售/Paid Pilot/付款 | 强付费证据 |
| 8 | 真实使用/留存/复购/扩张 | 强持续价值证据 |

原则：

> 分数不能只来自 1-2 级证据。一个机会要进入正式实验，至少要设计能拿到 4-7 级证据的动作。

## 11. 自动评分和人工评分的边界

### 11.1 适合自动评分的部分

适合自动化：

- 14 类 signal 命中数；
- 独立作者数；
- 独立域名数；
- anti-pattern 命中数；
- lifecycle signal 声量；
- attention / reselection / money / activation / outcome 比例；
- 问题簇 opportunity score；
- 近两年案例结构字段统计。

### 11.2 必须人工复核的部分

必须人工复核：

- 用户是否真的是买家；
- 帖子里的痛点是否真实高价值；
- 替代方案是否真的痛苦；
- 问价是否有真实预算；
- 交付是否能兑现；
- AI 输出质量是否可验收；
- 硬件成本和售后是否可承受；
- 合规/采购/责任边界是否会卡死；
- 这个机会是否只是短期热点。

### 11.3 最合理的方式

建议用：

```text
自动初筛分 + 人工复核备注 + 实验结果回填
```

而不是纯自动模型。

## 14. 三个示例判断

### 14.1 高分机会长什么样

典型特征：

- 用户已经在用 Excel、脚本、外包、旧软件；
- 用户反复抱怨耗时、出错、成本高；
- 有人在找替代方案；
- 有预算或现有支出；
- 能用一句话说清结果；
- 可以人工交付一次；
- 能找到目标名单；
- 交付成本未来可以自动化下降。

实验动作：

> 冷邮件 50 个目标用户，卖一个明确结果，要求用户给真实数据或当前流程，报价一个 paid pilot。

### 14.2 中分机会长什么样

典型特征：

- 有不少公开讨论；
- 有痛点描述；
- 但买家不清楚；
- 替代方案不够明确；
- 还没有问价/试用/迁移信号；
- 可能是趋势，也可能是真机会。

实验动作：

> 先做 10-15 个问题访谈，不急着做产品。目标是补清楚替代方案、预算 owner、发生频率。

### 14.3 低分机会长什么样

典型特征：

- 很多人觉得有趣；
- 没有明确用户；
- 没有替代方案；
- 没人问价；
- 没人愿意给数据；
- 只能靠发布热度；
- 做出来以后也不知道谁会反复用。

实验动作：

> 暂时杀掉，除非出现新的付费、迁移、试用、真实使用证据。

## 15. 当前数据缺口和 v2 升级方向

v1 可以先用，但要承认数据缺口。

### 15.1 需要补的数据

| 缺口 | 为什么重要 |
| -- | -- |
| 真实付费数据 | 判断用户是否真的愿意付钱 |
| 冷邮件转化数据 | 判断可触达性和 CAC |
| Paid Pilot 数据 | 判断 Offer 是否能成交 |
| 交付耗时数据 | 判断毛利和规模化 |
| 留存/复购数据 | 判断持续价值 |
| 成功/失败 outcome 标签 | 训练更可靠的评分模型 |
| 非 HN / 非 YC 数据源 | 降低技术圈样本偏差 |
| 硬件 BOM / 售后 / 退货数据 | 判断硬件机会是否真实可行 |
| B2B 采购周期和预算 owner 数据 | 判断企业机会是否能成交 |

### 15.2 应该补哪些来源

优先补：

- Reddit；
- GitHub Issues；
- Product Hunt；
- G2 / Capterra 评论；
- App Store / Play Store 评论；
- Kickstarter / Indiegogo；
- 公司关闭/失败复盘；
- 价格页；
- 招聘 JD；
- 行业论坛；
- 真实冷邮件实验记录。

### 15.3 v2 应该增加什么

v2 应该增加：

- 每个机会的真实实验结果；
- 发信量、回复率、会议率、报价率、成交率；
- 用户愿意给数据的比例；
- 人工交付耗时；
- 单次交付成本；
- 复用/续费/转介绍；
- 成功/失败/停滞 outcome 标签；
- 按品类单独调权重。

## 16. 最终使用原则

1. 不要把分数当真理。
2. 分数只用于排序，不用于证明成功。
3. 自动分高的机会，也必须人工复核。
4. 自动分低但你有强一手证据，可以重新评估。
5. 公开讨论只能证明有迹象，不能证明有人付钱。
6. 进入实验池前，必须能写出最小可销售 Offer。
7. 实验必须追求 4-7 级证据，而不是停在点赞、浏览、注册。
8. 分数应随着新实验结果持续更新。

最终一句话：

> 当前数据已经够建立“机会实验前筛选分 v1”。但它的用途是帮我们更聪明地选择先验证谁，而不是替代真实市场实验。
