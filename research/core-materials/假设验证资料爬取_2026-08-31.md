## 3. 证据等级、行为信号与付费信号

初步可建立以下证据层级：

| Level | 证据 | 信号强度 | 主要风险 |
|---|---|---:|---|
| L0 | 创业者自己觉得 | 极弱 | 自证偏差 |
| L1 | 网上有人讨论 | 弱 | 噪音、吐槽不等于购买 |
| L2 | 用户主动表达痛点 | 中弱 | 语言证据、样本偏差 |
| L3 | 用户正在搜索/比较方案 | 中 | 搜索不等于预算 |
| L4 | 留资、Waitlist、DM、预约会议 | 中 | 低成本行为，假阳性 |
| L5 | 报价请求、采购流程、LOI | 中强 | LOI 不等于收款 |
| L6 | 定金、预售、PO、Paid Pilot | 强 | 可能只是一次性尝试 |
| L7 | 真实使用、留存、复购、扩张采购 | 极强 | 需要较长周期 |

关键原则：

- 行为证据优先于语言证据。
- 付费证据优先于兴趣证据。
- 复购/扩张优先于第一次付款。
- 单一强信号可以显著更新判断，但不能自动证明规模化。
- 任何证据都要问：它证明了哪个变量？没有证明哪个变量？

## 4. MVP / Prototype / Demo / Fake Door 类型谱系

| 类型 | 主要验证 | 不能证明 | 典型用途 |
|---|---|---|---|
| Prototype | 技术/交互可行性 | 付费、渠道、复购 | 技术风险高时 |
| Demo / Video Demo | 用户是否理解、是否被吸引 | 真实使用、付款 | 复杂产品解释成本高时 |
| Landing Page | 点击、留资、文案吸引 | 真实购买、留存 | 早期需求/定位测试 |
| Waitlist | 兴趣和低成本承诺 | 订单、预算 | 消费品/开发者工具/AI 工具 |
| Fake Door | 对某功能或 Offer 的行为兴趣 | 支付意愿、交付可行 | 快速测功能/价值主张 |
| Concierge MVP | 人工交付价值 | 自动化可行、规模化毛利 | B2B、服务型软件、AI 工作流 |
| Wizard of Oz | 用户体验看似自动，后台人工 | 长期成本和规模化 | AI/自动化/推荐系统 |
| Manual MVP | 人工执行最终服务 | 软件标准化 | 先验证流程和需求 |
| Pre-order / Deposit | 支付意愿 | 复购、履约质量 | 硬件/消费品/课程/工具 |
| Paid Pilot | 企业预算、真实场景价值 | 可规模化销售 | B2B SaaS、工业、硬件 |
| LOI | 组织意向 | 收款 | Enterprise/B2B 长周期销售 |
| PO / Contract | 采购承诺 | 成功交付、复购 | 高客单价 B2B |

## 8. 第一笔钱与“路径一致性”

需要区分：

| 类型 | 证明了什么 | 没证明什么 |
|---|---|---|
| 定制开发收入 | 某客户愿意为解决问题付钱 | 标准化 SaaS 会被购买 |
| 咨询/人工服务收入 | 问题存在且有人愿意买服务 | 软件/硬件产品可规模化 |
| 预售/定金 | 用户愿意承担一定承诺 | 能交付、会复购 |
| Paid Pilot | 企业愿意进入真实试点 | 大规模采购、稳定 ROI |
| 首单正式合同 | 采购闭环存在 | CAC、毛利、交付成本、续费 |
| 复购/扩张 | 持续价值更强 | 市场足够大 |

判断“第一笔钱”是否有效，建议加入路径一致性：

1. 早期收入是否来自未来产品的同一用户群？
2. 是否解决同一类核心问题？
3. 交付方式是否能从人工逐步迁移到目标产品？
4. 定价逻辑是否与未来商业模式一致？
5. 客户购买原因是否被记录清楚？

负例：

- Airbnb cereal boxes 更像融资/营销/生存手段，不直接验证住宿市场。
- 定制项目赚钱但最终想做标准 SaaS，可能证明“服务需求”，没有证明“SaaS 需求”。

## 9. 实验设计、偏差与决策规则

| 问题 | 资料方向 | 初步结论 |
|---|---|---|
| 一次实验能否同时验证多个变量 | 创业实验、A/B、因果推断 | 可以，但变量越多，失败越难归因 |
| 是否必须统计显著 | A/B testing / sequential testing | 大流量优化需要显著性；高客单 B2B 早期更看真实订单和采购行为 |
| 销售实验样本是否随机 | customer discovery / field experiments | 探索期可找最痛客户；规模验证期需标准化样本选择 |
| 强信号是否能推翻弱信号 | Bayesian updating | 一个真实订单可大幅更新信念，但仍需判断是否可重复 |
| 实验价值怎么算 | Information Gain / Decision Impact / Cost | 好实验不只是赚钱，还减少关键不确定性 |
| 何时 Kill | Kill threshold / opportunity confidence | 应按关键瓶颈变量和证据链，不按单一 KPI |

可转化成系统规则：

```text
Experiment Value =
  Expected Information Gain
  * Decision Impact
  * Option Value
  / (Cash Cost + Time Cost + Reputational Cost + Opportunity Cost)
```

机会组合不应只做“最高评分机会”，而应保留：

1. 高置信度、低到中等收益的稳定验证机会。
2. 低置信度、高潜力的探索机会。
3. 资本冷门但需求强的反共识机会。
4. 失败信息价值高、能快速排除关键假设的实验。
